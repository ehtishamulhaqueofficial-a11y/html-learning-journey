# 🚀 My HTML Learning Journey

## 1 August 2025 — The Beginning

On **1 August 2025**, I started my journey into software development with HTML.

My goal was not simply to memorize HTML tags.

I wanted to understand:

* Why HTML exists
* How a web page is structured
* What each important HTML element does
* How different elements work together
* How page structure affects usability and SEO
* How multiple pages can be connected
* How forms collect user input
* How semantic HTML improves page structure
* How HTML concepts are actually used inside real projects

I started with the fundamentals and gradually moved toward building complete pages and projects.

---

# 📚 What I Learned in HTML

## 1. HTML5 Basic Structure

I learned the basic HTML5 boilerplate and the purpose of its major parts.

I studied concepts such as:

* `<!DOCTYPE html>`
* `<html>`
* `<head>`
* `<meta>`
* `<title>`
* `<body>`

Instead of only copying the boilerplate, I focused on understanding **why each major part exists and what role it plays**.

---

## 2. Comments, Paragraphs and Attributes

I learned:

* HTML comments
* Paragraph elements
* HTML attributes
* How attributes provide additional information or configuration to an element

This helped me understand the difference between the main HTML element and the additional information attached to it through attributes.

---

## 3. Headings and SEO

I learned the HTML heading hierarchy:

* `<h1>`
* `<h2>`
* `<h3>`
* `<h4>`
* `<h5>`
* `<h6>`

I also studied how heading structure can contribute to the organization and readability of a page and how proper document structure can support SEO.

This helped me understand that headings are not simply about making text look large or small. They also communicate the structure of the document.

---

## 4. Anchor Tags and Navigation

I learned how to use the `<a>` element to:

* Create links
* Connect different web pages
* Navigate between pages
* Open links in the same tab
* Open links in another tab
* Use attributes to control link behavior

I also learned how multiple HTML pages can be connected to create a basic multi-page website.

---

## 5. Images

I learned how to use the `<img>` element and its important attributes.

Topics included:

* `src`
* `alt`
* `width`
* `height`

I learned the importance of the `alt` attribute and how it can provide meaningful information when an image cannot be displayed.

I also practiced controlling image dimensions and learned why image sizing should be handled carefully to maintain appropriate proportions and layout quality.

---

## 6. Text Formatting Elements

I practiced various HTML elements used for displaying and formatting text, including:

* Bold text
* Italic text
* Underlined text
* `<big>`
* `<small>`
* `<hr>`
* `<br>`
* `<sub>`
* `<sup>`
* `<pre>`

I also learned the difference between `<pre>` and `<p>` and how their behavior and intended purposes differ.

---

# 🏗️ Page Layout and Semantic HTML

One of the important parts of my HTML learning was understanding **page structure**.

I learned semantic elements such as:

* `<header>`
* `<main>`
* `<footer>`
* `<section>`
* `<article>`
* `<aside>`

I learned that semantic HTML is not simply about replacing `<div>` with different tags.

It is about giving meaning to different parts of a webpage and creating a clearer document structure.

I also studied how proper page structure can contribute to accessibility, maintainability, readability, and SEO.

---

# 🧱 Non-Semantic HTML

I also learned non-semantic elements such as:

* `<div>`
* `<span>`

I learned where these elements are useful and how they differ from semantic elements.

This helped me understand that semantic and non-semantic elements have different purposes rather than one simply being a replacement for the other.

---

# 📋 Lists

I learned how to create and use:

* Ordered lists
* Unordered lists

I practiced using list structures to organize related information properly.

---

# 📊 HTML Tables

I learned how to create tables and understand their basic structure.

I practiced concepts such as:

* Tables
* Rows
* Columns
* Table headings
* Table data
* Structuring information inside tables

I implemented these concepts in my practice work rather than only studying their syntax.

---

# 📝 HTML Forms

Forms were another major part of my learning.

I learned:

* `<form>`
* `<label>`
* `<input>`
* Text input
* Checkbox
* Radio button
* Submit button
* Placeholder text

I learned how form elements are used to collect information from users and how different input types are designed for different kinds of data.

---

# 🖼️ Favicons and Metadata

I learned how to add a favicon to a webpage and why metadata is important.

I also explored HTML metadata and how information placed inside the `<head>` can provide important information about a webpage.

---

# 🔎 SEO and Lighthouse

I did not treat HTML as only a visual markup language.

I also explored the relationship between:

* Page structure
* Semantic HTML
* Metadata
* Accessibility
* Performance
* SEO

I learned how to inspect a website using browser developer tools and how to use **Lighthouse** to check website-related scores and identify areas that can be improved.

This helped me understand that building a webpage is not only about making it appear on the screen.

---

# 📄 Why `index.html` Matters

During my learning, I also learned why `index.html` is commonly used as the default entry page for many websites and web servers.

This gave me a better understanding of how a project with multiple HTML files needs a clear entry point so that the browser/server environment knows which page should normally be served first.

# 💡 My Learning Philosophy

I believe that learning a technology is different from simply memorizing its syntax.

My approach was:

> **Learn the concept → Understand why it exists → Implement it → Build something with it → Analyze the result.**

That approach helped me move from simply knowing HTML tags to understanding how those tags work together to build a webpage.

---

# 🤖 HTML in the AI Era

I also understand an important reality of learning development in the current AI era.

Today, AI tools can generate HTML very quickly.

Someone without deep technical knowledge can ask an AI tool to generate a webpage and receive working HTML almost instantly.

Because of that, I do not consider the ability to manually type HTML syntax alone to be a strong competitive advantage.

For me, the more valuable skill is understanding:

* What the code is doing
* Why the structure is designed that way
* How to evaluate AI-generated code
* How to modify generated code
* How to debug problems
* How to make technical decisions
* How to combine AI with actual engineering knowledge

I want to become someone who **uses AI as a productivity tool rather than depending on AI without understanding the technology underneath it.**

# 🧠 My View of the Modern Software Industry

I believe the modern software industry is changing.

Knowing only how to build a MERN application is no longer the complete definition of being a strong developer.

For me, a valuable modern engineer should gradually develop several dimensions of capability:

### Technical Skills

Understanding development technologies and being able to build, debug, maintain, and improve software.

### Problem Solving

Understanding the actual business or user problem before immediately writing code.

### Collaboration

Being able to work effectively with teammates, understand requirements, communicate decisions, and contribute to a shared codebase.

### Communication

Explaining technical ideas clearly and communicating effectively with both technical and non-technical people.

### AI Skills

Knowing how to use AI tools to improve productivity while still understanding and validating the generated work.

### Engineering Mindset

Thinking beyond:

> "Can I write this code?"

and increasingly asking:

> "Is this the correct solution to the actual problem?"

My goal is to develop all of these areas together.
